# Security Policy — Dr. Osmanov

## 1. Модель угроз

| Угроза | Риск | Меры защиты |
|---|---|---|
| Brute-force OTP | ВЫСОКИЙ | 3 попытки/код + 3 кода/час/номер + блокировка |
| Кража JWT | ВЫСОКИЙ | RS256, 15мин TTL, ротация refresh, httpOnly cookie |
| SQL-инъекция | ВЫСОКИЙ | Prisma — только параметризованные запросы |
| Path traversal (файлы) | ВЫСОКИЙ | UUID-имена файлов, resolve + startsWith проверка |
| IDOR (доступ к чужим данным) | ВЫСОКИЙ | Проверка владельца на каждый запрос в service-слое |
| XSS | СРЕДНИЙ | Next.js экранирование + CSP заголовки |
| CSRF | СРЕДНИЙ | SameSite=Strict cookies, проверка Origin |
| DDoS / абьюз | СРЕДНИЙ | Nginx rate limit + NestJS Throttler |
| Утечка данных через логи | СРЕДНИЙ | Маскировка PII, без телефонов/имён в логах |
| Несанкционированный доступ к файлам | ВЫСОКИЙ | Файлы через аутентифицированный endpoint, не public URL |
| Mass assignment | СРЕДНИЙ | Явный whitelist в DTO (class-validator) |
| Перебор ID ресурсов | СРЕДНИЙ | UUID v4 (непредсказуемые идентификаторы) |
| Подмена MIME-типа файла | СРЕДНИЙ | Двойная проверка: заголовок + magic bytes (file-type) |

## 2. Правила аутентификации

### OTP (одноразовый пароль)
- 4 цифры, срок жизни 10 минут, одноразовый
- Хранится как bcrypt-хеш (НИКОГДА не plaintext)
- Rate limit отправки: максимум 3 SMS на номер в час
- Rate limit проверки: максимум 3 попытки на один код
- Попытки инкрементируются ДО проверки (защита от timing-атак)
- IP-адрес отправителя маскируется и сохраняется

### Access Token (JWT)
- Алгоритм: RS256 (асимметричный — приватный ключ подписывает, публичный проверяет)
- TTL: 15 минут
- Payload: `{ sub: userId, role: Role, jti: uniqueId }`
- Передаётся в заголовке `Authorization: Bearer <token>`
- Приватный ключ: 4096 бит RSA, хранится в переменных окружения

### Refresh Token
- 64 байта crypto.randomBytes, передаётся как hex-строка
- Хранится в БД как bcrypt-хеш (НИКОГДА не plaintext)
- TTL: 30 дней
- Доставляется как httpOnly, Secure, SameSite=Strict cookie
- Ротация при каждом использовании (старый отзывается)
- При logout: удаляется из БД

## 3. Правила авторизации

### Принцип: всё запрещено по умолчанию
- Каждый endpoint помечен декоратором `@Roles()` — нет implicit доступа
- Публичные endpoint помечены явно через `@Public()`

### Матрица доступа

| Ресурс | CLIENT | STAFF | OWNER |
|---|---|---|---|
| Свои записи | Чтение, создание, отмена | - | - |
| Записи пациентов | - | Чтение, статус | Полный доступ |
| Свой профиль | Чтение, редактирование | Чтение | - |
| Профили пациентов | - | Чтение | Полный доступ |
| Мед. записи (свои) | Чтение | - | - |
| Мед. записи (все) | - | Создание, редакт. | Полный доступ |
| Документы (свои) | Скачивание | - | - |
| Документы (все) | - | Загрузка, скачивание | Полный доступ |
| Оплата | - | Создание | Полный доступ |
| Аналитика | - | - | Полный доступ |
| Управление персоналом | - | - | Полный доступ |
| Настройки клиники | - | - | Полный доступ |
| Каталог услуг | Чтение | Чтение | Полный доступ |
| Аудит-лог | - | - | Чтение |

### Проверка владельца (IDOR-защита)
- Проверка выполняется в service-слое, НЕ только в guard
- CLIENT: `resource.client.userId === requestUser.sub`
- STAFF: `resource.staffId === requestUser.staffId`
- OWNER: доступ ко всем ресурсам

## 4. Защита данных (152-ФЗ)

### Хранение персональных данных
- Телефоны хранятся как есть (необходимо для SMS)
- Медицинские записи доступны только пациенту и авторизованному врачу
- Аудит-лог хранится 1 год
- UUID идентификаторы (не последовательные ID)

### Право на удаление
- Пользователь может запросить удаление аккаунта
- Реализация: анонимизация (не hard delete)
  - `name` → "Удалённый пользователь"
  - `phone` → рандомная строка
  - `isAnonymized` → true
  - Медицинские записи сохраняются (требование законодательства), но без привязки к личности

### Ограничение передачи данных третьим лицам
- SMS.ru: передаётся ТОЛЬКО телефон (для отправки SMS)
- Telegram: передаётся ТОЛЬКО имя пациента (для уведомлений врачу)
- Никакие другие PII не отправляются во внешние сервисы

## 5. Безопасность файлов

### Загрузка (upload)
- Допустимые MIME-типы: `image/jpeg`, `image/png`, `image/webp`, `application/pdf`
- Максимальный размер: 20 МБ
- Двойная валидация типа:
  1. MIME-заголовок при загрузке (multer fileFilter)
  2. Magic bytes содержимого (библиотека file-type)
- Файлы загружаются в память (memoryStorage), обрабатываются, затем сохраняются
- Переименование в UUID (оригинальное имя НИКОГДА не используется в пути)
- Изображения обрабатываются через Sharp:
  - Удаление EXIF-данных
  - Ресайз до 1920px max
  - Конвертация в WebP
- PDF сохраняется как есть
- Вычисляется SHA-256 контрольная сумма

### Скачивание (download)
- Файлы НЕ доступны через статический URL Nginx
- `/uploads/` директория заблокирована (`deny all` в nginx)
- Доступ ТОЛЬКО через `GET /api/documents/:id/download`
- Проверка аутентификации (JWT)
- Проверка владельца (IDOR)
- Path traversal защита: `resolve()` + `startsWith(uploadDir)`
- Заголовок `X-Content-Type-Options: nosniff`

## 6. HTTP-заголовки безопасности

Устанавливаются через Helmet (NestJS) + Nginx:

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data:;
  connect-src 'self';
  frame-src 'none';
  object-src 'none';

X-Frame-Options: DENY
X-Content-Type-Options: nosniff
Strict-Transport-Security: max-age=31536000; includeSubDomains
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=()
```

## 7. Валидация входных данных

### Глобальная настройка ValidationPipe
```typescript
{
  whitelist: true,              // удаляет поля, не описанные в DTO
  forbidNonWhitelisted: true,   // выбрасывает ошибку при лишних полях
  transform: true,              // автоматическое преобразование типов
  transformOptions: {
    enableImplicitConversion: false  // без неявных конверсий
  }
}
```

### Правила валидации
- Телефоны: формат +7XXXXXXXXXX, нормализация через ParsePhonePipe
- Даты: ISO 8601 формат
- UUID: валидация формата через IsUUID()
- Строки: максимальная длина, trim
- Числа: диапазоны (цена > 0, длительность > 0)
- Enum: только допустимые значения
- Файлы: тип + magic bytes (библиотека file-type)

## 8. Защита от DDoS и абьюза

### Nginx rate limiting
```nginx
limit_req_zone $binary_remote_addr zone=otp:10m rate=3r/m;   # OTP: 3 запроса/мин
limit_req_zone $binary_remote_addr zone=api:10m rate=60r/m;   # API: 60 запросов/мин
```

### NestJS Throttler (дублирующий слой)
- Глобально: 60 запросов за 60 секунд
- OTP endpoints: 3 запроса за 60 секунд

## 9. Логирование и мониторинг

### Что логируется
- Все мутационные операции (POST, PATCH, DELETE) → AuditLog таблица
- Неуспешные попытки аутентификации
- Rate limit нарушения
- Ошибки 500

### Что НЕ логируется
- Пароли, OTP-коды, токены
- Полные телефоны (маскировка: +7***1234)
- Имена и диагнозы в системных логах
- Полные IP-адреса (маскировка: 192.168.***.*)

### Маскировка
```typescript
maskPhone("+79001234567") → "+7***4567"
maskIp("192.168.1.100")  → "192.168.***.*"
```
